# 二开功能使用指南

这份指南只讲当前二开功能的关键操作路径。部署、环境变量和完整接口说明请查看文末链接。

## 先记住这条主线

日常使用基本按下面的顺序完成：

1. 在 **渠道管理 → 上游站点** 添加普通上游。
2. 在 **渠道管理 → 账号与 API Key** 添加面板账号或直连 API Key；官方账号改去 **官方凭证池**。
3. 刷新连接状态和模型，并在 **路由** 确认通道已经生成。
4. 在 **下游密钥** 创建一个 `sk-...` 密钥。
5. 将 r-api 的 Base URL 和该密钥交给客户端，并在 **使用日志** 验证实际命中的上游凭证。

> [!IMPORTANT]
> r-api 只提供网关 Base URL 和下游 Key，不负责替 Codex、Claude Code 等客户端完成账号授权或写入客户端配置。

## 1. 接入上游并生成可用网关

### 添加站点

进入 **渠道管理 → 上游站点 → 添加站点**：

1. 填写站点名称和准确的主站点 URL。
2. 不确定平台类型时点击 **自动检测**。
3. 如果 API 地址和主站不同，在 **API 请求地址池** 添加一个或多个 Base URL。
4. 保存站点。

同一站点配置多个 API 请求地址后，网关会在这些地址之间调度；具体顺序和健康状态可在站点详情中维护。

### 站点总并发

在站点编辑表单设置 **站点总并发上限** 和 **并发等待时间（毫秒）**。上限留空表示不限，有限上限为 1–10000；等待时间为 0–60000 毫秒，默认 0 表示容量不足立即拒绝。

同一站点的全部账号、上游凭据和下游 Key 共用这组槽位；同一站点的多个 API 地址也共用限额。HTTP 和原生模型请求在发送前获取槽位，持有到响应体结束、取消或读取失败；WebSocket 按活跃生成计数，空闲连接不占用。降低上限不会中断已有响应，新请求会等到占用降至新上限以下。

容量等待与上游首字节计时分开。等待超时返回 `503`，错误码为 `site_capacity_unavailable`，不会惩罚上游地址、通道或凭据健康，也不会重放已经开始输出的请求。客户端断开会取消等待或停止活跃传输并释放槽位。

限额由共享数据库中的唯一槽位租约协调。多副本部署必须连接同一个 MySQL/PostgreSQL 数据库；独立数据库无法形成部署总限额。本地多个进程可以共享同一 SQLite 文件，但不要把 SQLite 文件当成跨主机数据库服务。租约默认有效期 90 秒，每 30 秒续期；进程失联后过期槽位可回收，失去租约的活跃请求会终止。续期与释放按租约 token 校验，旧持有者不能删除后继请求的槽位。

站点配置会随备份保存，运行时租约不导出；导入会清除旧运行时租约。旧站点和旧备份默认不限额、不等待。


### 添加连接

进入 **渠道管理 → 账号与 API Key**，根据上游类型选择：

- 有后台面板的中转站：进入 **面板账号 → 账号列表**，添加账号或 Session。
- 只有 Base URL + Key：进入 **直连 API Key**。
- Codex、Claude、Gemini CLI、Antigravity 等 Provider：进入 **接入管理 → 官方凭证池** 完成授权或导入。
- 需要浏览器登录态：使用下文的 **浏览器凭证**。

添加后执行一次 **刷新账户状态** 或 **刷新模型**。成功标志是账号显示可用模型，并且 **路由** 页面出现对应模型通道。

### 创建下游密钥

进入 **下游密钥 → 新增下游密钥**：

1. 填写名称，点击 **随机** 生成 `sk-...` 密钥。
2. 简单自用可以只保存名称和密钥。
3. 多项目共用时，再配置过期时间、请求/成本额度和最大并发。
4. 需要隔离资源时，展开 **高级配置**，限制模型、路由群组、站点或具体上游凭据。

交付给外部客户端的内容只有：

| 配置 | 填写内容 |
| --- | --- |
| Base URL | `https://你的域名/v1`；本机使用时通常是 `http://127.0.0.1:4000/v1` |
| API Key | 在 **下游密钥** 创建的 `sk-...` |

客户端会自动补 `/v1` 时，Base URL 改填根域名。具体示例见 [客户端接入](./client-integration.md)。

## 2. 管理浏览器凭证

### 手动保存凭证

进入 **系统与安全 → 安全凭证库 → 添加站点凭证**：

1. 选择已添加的站点。
2. 选择站点适配器允许的凭证类型。
3. 填写名称和凭证内容后保存。

保存后列表只显示指纹和元数据，不回显明文。凭证失效时使用 **撤销**，确定不再需要时再删除。

### 采集浏览器登录态凭证

适合必须在网页中登录、无法直接复制 Session 的站点：

1. 构建并加载浏览器扩展，见 [浏览器凭证扩展](./browser-extension.md)。
2. 进入 **渠道管理 → 浏览器凭证 → 创建任务**，选择站点和采集模式。
3. 复制一次性凭证采集链接，并在安装了扩展的浏览器中打开。
4. 在目标站点完成登录。
5. 打开扩展，领取任务、采集声明字段并提交。
6. 回到 **系统与安全 → 安全凭证库**，确认新凭证已经出现。

浏览器凭证任务和领取令牌都是一次性的；链接过期后重新创建，不要反复提交旧链接。

## 3. 余额同步、模型和自动签到

进入 **渠道管理 → 账号与 API Key → 面板账号 → 账号列表**：

- 点击单个账号的 **刷新**，同步余额和账号状态。
- 使用 **批量刷新余额** 更新全部支持余额查询的账号。
- 点击 **刷新模型**，同步模型并重建路由。
- 为需要签到的账号打开 **签到** 开关。

进入 **系统与安全 → 设置 → 自动化任务**：

1. 选择间隔签到或 Cron。
2. 配置执行时间和签到窗口。
3. 保存后可先点 **测试一次签到**。
4. 最终结果在 **签到记录** 查看。

> [!WARNING]
> **批量测活** 默认关闭。只有在上游明确允许真实探测请求时才开启；模型刷新本身不会顺带测活。禁止测活的站点应保持该开关关闭，也不要开启站点的“刷新后自动探测”。

## 4. 配置通知

进入 **通知设置**：

1. 启用需要的渠道，例如 Webhook、Bark、Server酱、Telegram 或 SMTP。
2. 填写该渠道的必要地址或凭据。
3. 在 **通知投递策略** 选择：
   - **宁可重发**：结果不确定时继续重试，尽量送达。
   - **宁可漏发**：结果不确定时停止，尽量避免重复通知。
4. 点击 **保存通知设置**。
5. 点击 **发送测试通知** 验证链路。

最近投递结果会显示在同一页面。状态为 **投递未知** 时，需要管理员确认是否重新排队。

如果要让本机 Codex / Claude Code 的 Hook 或 Notify 自动上报，请继续配置 Local Connector。

## 5. Local Connector 与 Hook / Notify

Local Connector 用于连接服务器上的 WebUI 和本机 Coding Agent。服务器只下发固定动作，不执行任意 Shell。

### 配对设备

1. 先构建服务端：`npm run build:server`。
2. 进入 **本地 Connector → 本地设置**，填写设备名并勾选所需权限。
3. 点击 **生成配对令牌**。
4. 在目标电脑执行页面生成的完整 `metapi-connector pair ...` 命令。
5. 执行 `metapi-connector status`，确认设备已配对。
6. 常驻运行：`metapi-connector run`。

远程服务器应使用 HTTPS；只有 `localhost`、`127.0.0.1` 和 `::1` 可以使用 HTTP。

### 一键安装 Hook / Notify

进入 **本地 Connector → 本地设置 → Hook / Notify 动作**：

1. 选择在线设备和 Agent。
2. 选择 `Hook` 或 `Notify`。
3. 选择 **安装**，然后点击 **创建动作**。
4. 等待动作状态变为成功。

安装和卸载前会在本机创建加密备份。需要恢复时选择 **回滚**，并填入之前动作返回的 `backupRef`。

## 6. Bridge 自动续跑

Bridge 用于 Codex 会话失败后的“继续”、换凭据或换渠道。它依赖具备 `app_server.control` 权限的在线 Connector。

本机运行：

```bash
codex app-server daemon start
export CODEX_APP_SERVER_USE_LOCAL_DAEMON=1
metapi-connector run --direct
```

设置环境变量后需要重启一次 Codex Desktop。Desktop 与 Connector 会连接同一个 managed App Server，因此飞书或 WebUI Prompt 会直接出现在原会话；不要使用 `--owned-app-server` 接管 Desktop 会话，它会启动隔离的第二个 App Server。

然后进入 **本地 Connector → 会话接管**，选择需要控制的活跃会话：

1. 从 Connector 已上报的会话列表进入设备工作台，不需要手填陌生 Thread。
2. 会话列表以活跃时间为主要时间信息，优先处理最近仍有活动的会话。
3. 续跑 Prompt 通常保持为“继续”。
4. 分别为 `429`、并发限制、服务临时不可用和 Codex 重试耗尽选择策略：
   - 保留当前线路
   - 轮换同站凭据
   - 切换 API 渠道
   - 停止续跑
5. 选择有限次数或无限续跑，再创建任务。

同一会话只会保留一个活跃控制任务。需要人工接管时，在任务详情发送 Prompt，选择 **补充当前轮** 或 **下一轮发送**；新人工 Prompt 会接管自动续跑。

## 7. WebUI / 飞书审批与 Prompt

### 在 WebUI 审批

保持 Connector 以 `--direct` 运行。Codex 出现命令、文件修改、权限或用户输入请求后：

1. 进入 **本地 Connector → 会话接管**，打开对应设备和会话。
2. 在请求队列选择一项，核对 Thread、请求类型和请求参数。
3. 选择允许、拒绝，或填写用户问题后提交。
4. 状态变为 **已完成**，表示响应已回到本机 Codex。

### 接入飞书

进入 **本地 Connector → 飞书**，选择要配置的设备：

1. 填写 Adapter 名称、App ID、接收目标、App Secret 和 Verification Token。
2. 填写 WebUI 的公网 HTTPS 地址和允许操作的飞书用户。
3. 保存后复制页面生成的回调地址。
4. 将该地址填入飞书应用的事件回调配置。
5. 回到 WebUI 查看投递记录，确认卡片已送达。

配置完成后，审批卡片可直接在飞书中处理。也可以在 **飞书主动 Prompt** 选择当前 Connector 已观测到的 Bridge 会话，向飞书发送一个可填写 Prompt 的卡片。

App Secret、Verification Token 和 Encrypt Key 会进入安全凭证库；编辑时秘密字段留空表示保持原值。

## 8. 日常检查入口

出现问题时按下面顺序查看：

| 问题 | 首选入口 |
| --- | --- |
| 请求失败、实际用了哪个站点或凭据 | **使用日志** |
| 路由没有生成或模型不可见 | **渠道管理 → 账号与 API Key → 刷新模型**、**路由** |
| 账号余额或状态不对 | **渠道管理 → 账号与 API Key → 面板账号 → 账号列表** |
| 自动签到失败 | **签到记录** |
| 通知未送达 | **通知设置 → 最近通知投递** |
| Connector 动作失败 | **本地 Connector** |
| 会话没有继续 | **本地 Connector → 会话接管 → 会话工作台** |
| 审批没有回到 Codex | **本地 Connector → 会话接管** 与 **飞书** 投递记录 |
